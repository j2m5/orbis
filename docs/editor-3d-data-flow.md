# Поток данных редактора

Все изменения 3D-сцены идут в одном направлении:

`React → EditorStore → OrbisEditorBridge → Orbis / AstroControls / Planet → Three.js`

- React-панели отображают состояние и вызывают только actions соответствующей части `EditorStore`.
- `EditorStore` — единственный источник редактируемых значений для UI, сохранения проекта и будущих undo/redo.
- `OrbisEditorBridge` наблюдает за снимками `orbis`, `controls`, параметрами `planet` и изменениями файлов текстур, после чего передаёт их в 3D-ядро. MobX не участвует в рендер-цикле.
- `Orbis` владеет глобальными настройками сцены, `AstroControls` и главным редактируемым экземпляром `Planet`.
- `AstroControls` применяет настройки камеры и самостоятельно поддерживает состояние пользовательского ввода.
- `Planet` сам владеет своим `object3D`, применяет параметры и управляет жизненным циклом загруженных текстур.

## Глобальные настройки Orbis

Секция `EditorStore.orbis` управляет:

- цветом фона;
- видимостью, размером, делениями, цветами и прозрачностью сетки;
- видимостью осей и маркера источника света;
- масштабом рендера относительно `devicePixelRatio`.

Изменение размера, количества делений или цветов пересоздаёт `GridHelper`. Видимость и прозрачность обновляются на существующем helper. Число делений всегда чётное, чтобы `GridHelper` мог выделить центральные линии.

## Текстурные ресурсы Planet

Ручная загрузка текстур проходит отдельно от сериализуемого snapshot параметров:

`TitanFileInput → PlanetTextureAssetStore → OrbisEditorBridge → Planet.loadTexture() → ImageBitmap → Three.Texture → shader uniform`

- `PlanetTextureAssetStore` хранит выбранный `File`, номер ревизии, статус загрузки и текст ошибки. `File` наблюдается по ссылке и не преобразуется MobX.
- Bridge реагирует на ревизию конкретного текстурного слота. Поэтому повторный выбор того же файла тоже запускает загрузку.
- Только `Planet` декодирует `Blob`, создаёт `Texture`, назначает цветовое пространство и подменяет shader uniform. Цветовые карты декодируются из sRGB в линейное рабочее пространство, а shader конвертирует итоговый цвет в output color space renderer.
- Пока новый файл декодируется, последняя корректная текстура остаётся на объекте. При ошибке она не теряется.
- Номер запроса защищает от гонок: результат старой загрузки не может заменить более новый выбор или восстановить очищенную текстуру.
- При замене, очистке и `Planet.dispose()` принадлежащие планете GPU-текстуры освобождаются вместе с исходными `ImageBitmap`.

Захардкоженной загрузки `storage/moon.jpg` и `storage/night.jpg` при старте больше нет. Без выбора файлов соответствующие uniforms остаются пустыми.

## Как добавить параметр

1. Добавить поле и значение по умолчанию в `src/core/contracts.ts`.
2. Добавить observable-поле, action и поле в `snapshot` нужной секции `EditorStore`.
3. Применить новое поле в `Orbis.applySettings`, `AstroControls.applySettings` или `Planet.applyParameters`. Для дорогих операций сначала сравнить новое значение с текущим.
4. Добавить React-контрол в соответствующую панель.

Сам `OrbisEditorBridge` при этом менять не нужно: он уже передаёт полные типизированные снимки трёх секций.

## Как добавить текстурный слот Planet

1. Добавить имя слота в `PLANET_TEXTURE_SLOTS` из `src/core/contracts.ts`.
2. Создать для него `PlanetTextureAssetStore` в `PlanetStore.textures`.
3. Добавить shader uniform и его конфигурацию, включая корректное цветовое пространство, в `Planet`.
4. Добавить подпись поля в `PlanetTexturesPanel`.

Все три таблицы описаны через `Record<PlanetTextureSlot, ...>`, поэтому TypeScript укажет на пропущенные обязательные места. Реакции bridge и поля UI создаются по общему списку слотов и отдельно расширять их не требуется.
